# 门店投流预算自动对账

把总部流量激励名单和巨量本地推消耗导出表放在本地运行，自动汇总每家门店的消耗、预算使用率和异常名单，并生成 Excel。真实经营数据只在本机处理；仓库只包含虚构的测试样例。

## 快速开始

需要 Python 3.10 或更新版本。

```bash
python -m pip install -r requirements.txt
python store_recon.py --roster 激励名单.xlsx --spend 本地推导出.xlsx --out 核对结果.xlsx
```

如果消耗数据分成多个导出文件，可以一次传入：

```bash
python store_recon.py --roster 激励名单.xlsx --spend 100家-1.xlsx 100家-2.xlsx 100家-3.xlsx --out 核对结果.xlsx
```

也支持 CSV/TSV。程序会在前30行里寻找表头；如果文件使用非默认工作表，可以指定：

```bash
python store_recon.py --roster 激励名单.xlsx --roster-sheet 激励名单 --spend 本地推导出.xlsx --spend-sheet 消耗明细
```

支持的名单字段至少包括“门店名称”和“预算”，常见列名如“激励名单门店”“激励预算（元）”也能识别。消耗表至少包括“门店ID”“门店名称”和“消耗”，并尽量提供“城市”。字段名暂不匹配时，修改 Excel 表头或在 `ALIASES` 中加入后台使用的列名即可。

## 匹配规则

1. 激励预算仅接受300、600、900元。明确标记“无激励/不参与”或预算缺失、不在这三个档位的行会放入“已剔除”，不会计入统计。
2. 有名单门店ID时按ID定位；名单和后台都提供城市时，还会校验城市一致。ID和城市冲突会进入“待确认”。
3. 没有ID时，程序按标准化后的门店名称匹配；存在城市时一并校验。重复同名候选不会自动选择。
4. 近似名称只显示为候选提示，**不会自动确认或计入匹配结果**。确认后可用映射表维护别名和门店ID。
5. 实际消耗大于预算标记“已超预算”；消耗达到预算80%且不超过预算标记“临近预算”。恰好等于预算不算超支。
6. 待确认门店不计入预算和消耗汇总。多份消耗表按门店ID合并累加。

映射表为 CSV 或 Excel，至少两列：

```csv
激励名单门店,门店ID
新店名单上的别名,1234567890123456789
```

使用时增加 `--mapping 门店映射.csv`。映射只在本机提供，不需要写入公开仓库。

## 结果文件

输出工作簿包含“核对摘要”“核对明细”“待确认”“超预算”“临近预算”“已剔除”工作表。摘要统计仅覆盖已确认匹配门店。请人工查看“待确认”中的候选提示，并在下一轮用确认后的映射表减少重复判断。

## 测试

```bash
python -m unittest discover -s tests -v
```

测试数据在 `tests/fixtures/`，使用虚构门店名和虚构ID。10月15日已完成核对表仅在本地用于历史校验，没有上传到仓库。若你有权访问该文件，可在本机执行历史对照测试：

```bash
HISTORICAL_REFERENCE_XLSX="/本机路径/总部流量激励门店_预算消耗核对总表_20261015.xlsx" python -m unittest discover -s tests -v
```

该对照仅检查历史基准汇总：177家匹配、11家待确认、43家超预算、消耗75803.40元、超支16711.28元。它不是新一期数据的核对结果。

## 隐私提示

不要把后台导出、实际名单、客户信息或带真实门店ID的映射表提交到公开仓库。`.gitignore` 已忽略常见 Excel/CSV 导出和生成的核对结果；导入和输出文件默认留在你自己的电脑。
